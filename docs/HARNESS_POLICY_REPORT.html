전체 진행을 요청하면 준비된 단계를 순서대로 이어갑니다. 특정 단계까지만 요청하면 그 단계의 결과를 보고하고 멈춥니다.

  1. 01

    프로젝트 시작

    START

    프롬프트와 고객 문서를 바탕으로 해결할 문제와 원하는 결과를 파악합니다.

    수행
    목표·사용자·범위·제약을 확인하고 가능성과 부족한 정보를 살펴봅니다.
    산출물
    프로젝트 개요, 포함·제외 범위, 자료 목록과 확인할 질문.
    완료 기준
    무엇을 왜 만드는지 설명할 수 있고, 중요한 불확실성과 확인 대상이 드러납니다.
  2. 02

    요구사항 정리

    REQUIREMENTS

    고객의 요청을 구현과 검증에 사용할 수 있는 구체적인 요구사항으로 정리합니다.

    수행
    기능·품질·데이터 요구, 우선순위와 완료 기준을 정리하고 충돌을 해소합니다.
    산출물
    요구사항 목록, 기능별 완료 기준, 자료와의 연결, 보류 범위.
    완료 기준
    이번에 만들 범위가 명확하고, 각 요구의 충족 여부를 확인할 수 있습니다.
  3. 03

    설계

    DESIGN

    요구사항을 어떻게 구현할지 구조와 동작을 구체화합니다.

    수행
    화면·사용 흐름·구성 요소·데이터·연결 방식·예외 처리를 설계합니다.
    산출물
    설계 설명, 화면·데이터·인터페이스 정의, 기술 선택과 검증 접근.
    완료 기준
    요구사항이 설계에 반영되고, 구현에 필요한 연결 관계와 중요한 기술적 판단이 정리됩니다.
  4. 04

    계획 작성

    계획 작성 완료

    설계를 실제로 수행할 작업으로 나누고 순서와 검증 방법을 정합니다.

    수행
    작업 목록·우선순위·의존성·수정 범위·검증 방법·일정과 위험을 정리합니다.
    산출물
    작업 계획, 수행 순서, 사전 점검 결과와 미확정 사항.
    완료 기준
    요청한 계획을 작성하고 필수 사전 점검을 통과합니다. 실패한 항목은 보완 필요로 보고합니다.

    계획만 요청했다면 여기서 종료합니다. 실행 결정이나 구현 허가를 계획 작성 완료 조건으로 요구하지 않습니다.

  5. 05

    실행 준비

    실행 준비 완료

    준비한 범위·가능성·영향·검증 계획을 설명하고 실제 수행 여부를 결정합니다.

    수행
    필요한 사용자 결정을 한 번 받고, 그 결정을 반영해 작업의 권한과 선행 조건을 확인합니다.
    산출물
    실제 진행 결정, 반영된 계획, 시작할 수 있는 작업.
    완료 기준
    현재 계획의 실행이 허용되고, 시작할 작업의 필수 실행 조건이 충족됩니다.

    같은 범위에 대한 유효한 결정이 이미 있다면 다시 묻지 않습니다. 결정 대기·보류·거절 상태에서는 해당 구현을 시작하지 않습니다.

  6. 06

    구현

    IMPLEMENTATION

    준비된 작업을 순서대로 수행하고 기능과 결과물을 만듭니다.

    수행
    기능을 구현하고 작업 중 필요한 검사를 수행합니다. 실제 의존성과 사용자 우선순위에 맞춰 진행합니다.
    산출물
    구현된 기능과 결과물, 수행 내역, 발견한 문제와 남은 작업.
    완료 기준
    해당 범위가 구현되어 검증할 수 있습니다. 구현 완료와 검증 완료는 구분합니다.

    새 요구나 중요한 영향이 발견되면 가능성·영향을 설명하고 진행을 결정한 뒤, 영향받는 요구사항·설계·계획 단계부터 반영합니다.

  7. 07

    검증

    VERIFICATION

    구현된 결과가 요구사항과 완료 기준을 충족하는지 확인합니다.

    수행
    필요한 기능·통합·화면·환경 검사를 수행합니다. 수정이 허용된 결함은 구현 단계로 돌아가 보완하고 재검증합니다.
    산출물
    검증한 버전, 검사 결과, 결함 처리 내역과 남은 한계.
    완료 기준
    필수 검사를 통과하고 전달을 막는 결함이 해소됩니다. 미실행·실패 검사는 통과로 표시하지 않습니다.

    검증만 요청했다면 발견 사항을 보고하고 멈춥니다. 변경된 부분과 영향받는 부분을 검사하며, 기존 결과는 여전히 유효한지 확인한 뒤 재사용합니다.

  8. 08

    고객 인수 확인

    ACCEPTANCE

    검증된 결과물을 고객에게 제시하고 합의한 인수 기준의 충족 여부를 확인합니다.

    수행
    결과물을 시연·검토하고 고객 의견을 정리합니다. 필요한 최종 인수 결정을 받습니다.
    산출물
    인수 대상 버전, 고객 확인 결과, 남은 의견과 처리 방침.
    완료 기준
    프로젝트에 필요한 인수 기준과 최종 승인 요건이 충족됩니다.

    최종 고객 인수에는 정해진 별도 승인 절차가 적용됩니다. 인수가 계약상 해당하지 않으면 그 근거를 명시하고 다음 단계로 진행합니다.

  9. 09

    배포·전달

    DELIVERY

    확인된 버전을 합의한 환경이나 전달 방식으로 제공합니다.

    수행
    전달 대상·설정·절차·복구 준비를 확인하고, 필요한 승인을 충족한 뒤 배포하거나 결과물을 전달합니다.
    산출물
    전달된 버전, 변경 안내, 사용 안내와 전달 후 확인 결과.
    완료 기준
    합의한 대상에 결과물이 전달되고 필요한 전달 후 검사가 완료됩니다.

    운영 배포에는 해당 배포 승인이 필요합니다. 파일 전달 등 운영 배포가 없는 프로젝트는 합의한 전달 방식으로 완료합니다.

  10. 10

    인계·프로젝트 종료

    CLOSE

    운영과 후속 대응에 필요한 내용을 인계하고 프로젝트의 남은 의무를 정리합니다.

    수행
    사용·운영 문서, 담당자, 유지보수와 장애 대응 방법을 인계하고 미해결 사항의 처리와 종료 기준을 확인합니다.
    산출물
    최종 결과 정리, 인계 자료, 유지보수 준비 내용과 남은 의무의 처리 결과.
    완료 기준
    필요한 전달·인수·인계·유지보수 준비와 종료 기준을 충족합니다. 종료를 막는 미완료 의무가 없습니다.
